## 2025-11-05 - [Replace Intermediate Collection Allocation with Direct Map Query]
**Learning:** In the `emit_sla_alerts` function within `orch8-engine/src/scheduler.rs`, the original code allocated a `HashSet` from a map's keys to perform existence checks. An attempt to optimize this by directly querying the `HashMap` via `.contains_key(&(c.instance_id, c.block_id.clone()))` was rejected because `BlockId` wraps a heap-backed String. Cloning `BlockId` to construct the lookup key causes a heap allocation on every single check, negating the zero-allocation intent and regressing performance compared to the original code which pre-allocated a `HashSet` of borrowed keys.
**Action:** When optimizing hot path lookups against collections with heap-backed keys, do not use `.clone()` to construct keys for `.contains_key()`. If borrowed-key lookups are required and the collection does not natively support them (e.g., standard `HashMap` without a custom `Borrow` implementation), pre-allocating an intermediate lookup structure (like a `HashSet` or `Vec`) with borrowed keys *is* the correct, zero-allocation-per-iteration approach.
