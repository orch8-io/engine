# Frozen definition and input protocols 1 (staged)

This server/client codec is unpublished. It does not activate delegated execution:
claim-side capability negotiation, reference delivery, private materialization and
remote-authority checks before local forward work remain required. The shared
models and verifier live in `orch8_types::delegation_definition`, without a database
runtime dependency when default features are disabled.

## Expected identity and scope

A client verifies a response against a reference and scope obtained independently
from its trusted claim. Copying the response's own digest into the verifier does
not establish provenance. HTTP authentication and the recorded claim reporter
still apply to `GET /workers/tasks/{id}/definition`; the response is `no-store`.
The reader checks authority again after encoding the response.

The scope contains `tenant_id`, `task_id`, `worker_id` and `claim_epoch`. The epoch
is canonical unsigned decimal **text**, supporting the full `u64` range without
JavaScript number rounding. Zero, empty worker identity and nil task identity
are invalid scope. Leading zeros, signs, whitespace, numeric JSON epochs and
overflow are rejected by the wire codec. Account/catalog/server identity remains
an explicit caller configuration for cache installation; a server-supplied scope
must not choose another local account's credentials or catalog.

A `DefinitionBundleReference` contains these fields:

| Field | Meaning |
| --- | --- |
| `version` | Wire codec version, currently 1 |
| `sequence_sha256` | Existing published root semantic fingerprint |
| `bundle_sha256` | Semantic manifest fingerprint, including pinned selections |
| `payload_sha256` | SHA-256 of the exact decoded UTF-8 payload bytes |
| `payload_bytes` | Exact decoded byte count, at most 4 MiB |
| `definition_count` | Root plus dependencies, from 1 through 256 |
| `selector_count` | Distinct typed name/version selections, from 0 through 1024 |

Runtime resource limits may be smaller. A root-only client may support one
definition and zero selectors. References exceeding a client's negotiated limits
must not be admitted as new work. This capability/claim filtering is the next
integration step; it is not implemented by the codec itself. Facts from older
issued claims retain their separate reporting/reconciliation contract.

## Exact payload bytes

Decoded definition values have a separate 16 MiB logical expansion budget.
Accounting charges 64 bytes per JSON value or object key plus UTF-8 string
bytes, shared across all definition documents. This is a resource admission
measure, not an allocator-specific heap bound. Clients can lower this budget
independently of the serialized-byte limit. Array limits reject excess elements
before decoding them. Publication rejects invalid or oversized closures with a
conflict and rolls back admission, leaving the grant available for a corrected
retry. Dynamic task input is outside the definition budget and needs its own
admission limit.

Public parser errors and definition-model debug output omit private definition
values. Authorized serialization still retains the original payload.

The JSON envelope contains `version`, `scope`, `reference`,
`payload_encoding: "json_utf8_base64"` and `payload_base64`. The base64 uses the
standard alphabet and padding. A downloader must bound the HTTP envelope before
parsing it; the existing 8 MiB download ceiling leaves room for a 4 MiB payload's
base64 and metadata. The verifier checks scope/reference equality, expected
encoded length, decoded length and SHA-256 before parsing payload JSON.

Codec 1 constructs this wrapper around the **retained** manifest/document text:

```json
{"manifest":{},"definitions":[{"version":1,"sequence_sha256":"...","definition":{}}]}
```

This is a shape illustration, not a valid bundle. Documents are sorted by their
semantic hash. Real manifest and definition JSON replace the empty objects.
Their exact retained text is copied into the wrapper; it is not regenerated by
serializing current workflow structs. The wrapper field order and delimiters are
fixed for codec 1. Shared body deduplication can preserve an older creation time;
the reference is calculated from those retained bytes after deduplication.

Publication stores wire version/hash/size/count metadata with its immutable
manifest. Readers reconstruct the same bytes and compare the complete reference.
A mismatched reference is an integrity error. An absent historical manifest is
unavailable and is never inferred from today's catalog. Manifest/body writes and
reference metadata commit atomically with the grant, mailbox and publication.
No second full payload copy is stored per publication.

## Semantic and structural verification

The existing root fingerprint stays unchanged: sorted Rust JSON with only
`created_at` removed. The separate wire digest avoids requiring another language
to reproduce Rust float formatting or key sorting. Both identities are checked by
the shared Rust verifier. A raw document's semantic identity is checked before
its compatible typed defaults are applied, so newly defaulted struct fields do
not rewrite an older retained fingerprint.

Typed validation checks the complete reachable dependency graph, scope,
name/version selections, unique sequence IDs and catalog versions, body hashes,
manifest version and resource bounds. Extra, missing or conflicting documents
and bindings fail closed. The result is a `VerifiedDefinitionGraph`; this proves
content consistency, not permission to execute provider effects. Local execution
also needs the current remote claim, a durable run binding and its own forward
admission fences after restart.

The [captured compatibility vector](../contracts/vectors/delegation-definition-v1.json)
includes integer-looking floats, negative zero, `u64::MAX`, values above
JavaScript's safe integer range, exponent notation, the smallest positive
subnormal float, NUL and BMP/non-BMP keys. Its legacy semantic fingerprint was
captured before extracting the verifier from storage. Rust, Node/WebCrypto and
Python tests check the same bytes. JavaScript parse/stringify rounds an integer
in this vector; Python reserialization also changes its byte identity. Neither
round trip may replace the authenticated payload. SDKs should pass retained bytes
to the shared verifier/materializer rather than re-encode parsed definitions.

Protocol models reject unknown wrapper fields. New semantic or encoding fields
require an explicit compatible codec/version strategy; do not silently change
codec 1's bytes or reinterpret unsupported documents.

## Delegated decoder capabilities (staged)

`RuntimeCapabilities.delegation_protocol` is an optional typed opt-in. Its absence
means no declared frozen-definition/input execution support; handlers, runtime
kind and build version must not substitute for it. The current mobile bridge
still emits no descriptor. Registration and authenticated storage claim requests
validate a supplied descriptor. Device destination discovery preserves these
limits while continuing to omit private runtime inventory and normalize trust.

Descriptor version 1 names definition wire version 1 and input wire version 1.
It separately limits definition payload bytes, definition count, selector count,
definition expansion, input payload bytes and input expansion. Wire values are
bounded `u32` numbers. Zero selectors is valid for a root-only client; definition
count and byte budgets must be positive. Hard ceilings are 4 MiB per payload,
16 MiB logical expansion per payload, 256 definitions and 1024 selectors. Clients
may tighten these bounds. Unknown versions, incomplete descriptors, unknown
fields, negative/fractional/string/overflowing numeric limits, and bounds above
the hard ceilings are rejected. Legacy advertisements remain readable and omit
the optional field when serialized. Rust struct-literal callers initialize the
new optional member explicitly.

`DelegationResourceUsage` must come from immutable publication metadata. The
compatibility predicate checks the complete definition reference and independent
input/expansion usage, rejecting zero/unknown usage and incompatible codecs. It
proves compatibility only; permissions, handler requirements, lease, issuer,
current scope and physical admission remain separate checks. SQL filtering before
LIMIT and revalidation under the claim lock are not wired yet. Do not advertise
or activate this contract until publication metadata, trusted claim delivery and
the native execution bridge enforce it.

## Delegated input wire codec 1 (staged)

Input has a separate `DelegationInputReference`: version, SHA-256 of exact UTF-8
JSON payload bytes, serialized byte count and exact logical expansion charge.
The envelope contains version, the same full claim scope used by definitions,
publication `request_sha256`, the reference, `json_utf8_base64` encoding and the
base64 payload. All expected identity must come independently from a trusted
claim. A response's own digest/reference cannot establish publication provenance.
The publication-request hash binds the larger original request and is not a hash
that a client can derive from input alone.

The shared Rust encoder charges the decoded value before serialization and
writes through a bounded buffer, including JSON escaping growth. Default hard
ceilings are 4 MiB serialized and 16 MiB logical expansion. The charge is 64 bytes
per value or object key plus UTF-8 string/key bytes, independently of definition
budgets. This is a logical resource bound, not a process-heap measurement. The
reader checks scope, request/reference equality, declared limits and encoded
length before base64 decoding, then exact byte count/SHA-256 before JSON parsing.
Decoded growth is bounded while building the value, and its consumed charge must
exactly match the reference. Trailing values, malformed UTF-8/JSON/base64, unknown
wrapper/reference fields and incompatible versions fail without private values
in errors or Debug output. Claim epochs remain canonical decimal text.

An input envelope fits under the client's existing 8 MiB response cap, but the
transport must enforce that cap before JSON envelope parsing. Claims should carry
references and usage metadata rather than duplicate full input in a poll batch;
the authenticated input-read and poll projection still need implementation.
Publication must atomically retain the original input bytes/reference with its
grant and mailbox, honoring encryption decorators. Reads must preserve those bytes
rather than regenerate them with a future serializer. These publication/transport
steps are not implemented by the standalone codec.

The [input vector](../contracts/vectors/delegation-input-v1.json) has an
independently Python-calculated byte digest and logical charge. Rust,
Node/WebCrypto and Python verify the same bytes, including `u64::MAX`, an integer
above JavaScript's safe range, negative zero, subnormal/exponent floats and
Unicode/NUL data. Host JSON parse/stringify changes the byte identity and can round
numeric values. Pass retained payload bytes to the shared Rust verifier; do not
replace them with a host-language JSON round trip. A verified value proves content
and expected-provenance equality, not permission to schedule provider work.

## Required execution integration

Use one shared Rust materializer for verified graphs and scoped local catalogs.
Mint private local sequence IDs and commit source-to-local mappings atomically
under explicit account, catalog and server identity. A private namespace alone
does not prevent remote UUIDs from overwriting globally keyed local records.
Resolve dependencies exclusively through pinned manifest selections.

Persist remote claim identity, full-width epoch and local run binding before
execution. Restart, cancellation, lease, ownership and revocation checks must
gate forward provider work. Negotiate codec, DSL/schema, graph counts, serialized
and expanded bytes, concurrency, and separate task/context/input/artifact budgets
before accepting a claim. Actual SDK reopen, execution, replay, acknowledgement
and cleanup probes, including cross-account/server/claim cases, remain required.

The staged `VerifiedDefinitionGraph::prepare_local` implements the pure relocation
part: it consumes the checked graph, mints a fresh private namespace and local
sequence IDs, clears remote embedding ownership, and pins every typed dependency
to its manifest-selected version. It preserves opaque handler JSON. Its plan
retains source hashes separately from the changed local definitions. Preparing
twice intentionally yields different local IDs; a persistent installer must
atomically store the plan and scoped receipt, then reuse that receipt on retry.
It is not yet wired to claim handling or SDK execution. Execution policies,
placement, handler credentials and all remote authority checks still require
local admission; successful preparation grants none of those permissions.


The staged mobile `install_claim_definitions` stores a verified graph and its
mapping atomically. Expected server, scope and reference must come from trusted
host claim context. The key includes account, catalog, local owner epoch,
canonical HTTPS server URL and all remote claim scope fields. A changed reference
for the same key fails. A retry reuses the receipt only after checking local row
ownership, definition count, root mapping, native fingerprints and byte totals.
Native fingerprints describe the SQLite representation; editor-only metadata
omitted by SQLite does not replace the original wire/source identities.

Local cache quotas account for codec-framed native projection bytes, excluding database
page/index/receipt overhead. They are independent of run admission: at most
128 receipts / 64 MiB
globally, 64 / 32 MiB per account and 32 / 16 MiB per catalog, with an 8 MiB maximum
native graph. Old epochs remain charged until explicit acknowledged compaction is
implemented. Existing valid receipts remain retryable at capacity. The installer
creates no run, schedules no provider work and grants no credential access. It
remains an internal staged boundary pending claim negotiation, durable run
binding and restart/authority admission.


The local installer also applies the existing mobile descriptor bound (4096
UTF-8 bytes, no control characters) to remote tenant and worker identity metadata;
the wire scope's tighter worker-length limit still applies. Receipt metadata
cannot consume an unbounded amount outside the native-definition byte quota.
Reopen tests currently retry with the verified envelope supplied again. Offline
receipt-only loading and actual native SDK execution are not established by that
check.


## Staged durable logical run binding

The internal mobile cache now retains the authenticated manifest. With an
independently trusted scope/reference, `load_claim_definitions` can check its
manifest digest, source mappings, native fingerprints, root and byte totals
without downloading the envelope again. An absent staged manifest is unavailable
until a verified envelope repairs it in the same transaction as graph validation;
a corrupt existing manifest is not silently replaced.

`bind_claim_run` stores one logical run ID per local account/catalog, canonical
server URL, remote tenant and task. Local sign-in epochs, worker IDs and remote
claim epochs do not form that stable key. Binding a later generation retains the
original graph and local run ID, validates the retained graph receipts and latest
claim observation, and updates the observed claim under the active local session
fence. Lower epochs
and another worker at the same epoch fail. Epochs are canonical full-width decimal
text and compared as `u64`, never signed SQLite integers. Reopening the same local
account does not manufacture another logical run for the same remote task.

Use `try_bind_claim_run` before downloading or installing another graph. `Some`
reuses a verified graph for the existing logical run, including at graph-cache
capacity and across sign-in epochs. `None` means a new run has no installed graph;
only that case needs the envelope installation path. An error means invalid or
unavailable retained evidence and must not be converted into a download/replace
fallback. Expected claim, reference and request identity must be supplied from
trusted provenance each time. This flow is internal and still needs wiring into
claim negotiation and the native SDK execution path.

One versioned latest-observation record per logical run holds the local owner
epoch, full remote claim scope, complete bundle reference, publication request
hash and graph receipt ID. The binding and observation update atomically. Both
SQL storage and the reader enforce a 16 KiB record bound; the reader checks stored
byte length before fetching JSON. No graph receipt is created for each successive
claim when the cached binding is reused. Missing advanced observations, unsupported
versions or changed fields fail without restamping. A pre-observation staged
binding is supported only when its immutable graph receipt independently matches
the complete retained claim and local owner epoch. This compatibility rule is
separate from native cache codec compatibility and is not a released-platform
upgrade proof.

The binding also pins an independently trusted publication-request SHA-256,
covering request identity separately from frozen definitions. A changed request
fingerprint fails even if the definitions match. This argument must come from
trusted publication provenance; shape/equality checks do not validate actual
input bytes against the fingerprint. Claim-side delivery/derivation and separate
task/context/input budgets remain required.

These methods create no native instance, acquire no provider permission, and do
not establish a current remote lease. A returned binding is retained identity,
not execution authorization. Native materialization, cancellation/revocation,
forward checks, physical callback admission, late-fact reconciliation and
acknowledged compaction still need integration. Native cache codec 1, defined
below, validates persisted fields before applying current typed defaults. Actual SDK upgrade probes remain required before platform
activation.


## Native cache fingerprint codec 1

This local fingerprint is separate from source semantic and wire-byte identities.
The receipt records an explicit native codec. Missing/unsupported codecs remain
unavailable; neither cache reads nor a repeated envelope silently restamp them.
Pre-codec unpublished caches therefore require an explicit supported migration or
import policy before activation. The schema-73 upgrade creates empty cache tables.

The SHA-256 input starts with UTF-8 `orch8.native-definition.v1` followed by one
NUL byte. These SQLite columns follow in this fixed order:

```text
id, tenant_id, namespace, name, version, deprecated, status, blocks,
interceptors, input_schema, sla, on_failure, on_cancel, placement,
created_at, sub_tenant, embed
```

`version` and `deprecated` are cast to SQLite decimal text. Other present fields
use their exact stored UTF-8 text, including JSON formatting and timestamp text.
Each SQL NULL is one zero byte. Each present field is byte `1`, its UTF-8 byte
length as unsigned 64-bit big-endian, and those bytes. Empty text and SQL NULL are
distinct. `definition_bytes` accounts for the complete framed projection, including
the prefix. The same 8 MiB per-graph and aggregate cache quotas apply; database
pages, indexes, manifests and other receipt overhead are outside this measure.

Raw BLOB lengths are bounded before fetching field text. The fingerprint is
checked before typed JSON decoding, so corruption cannot first expand a dense
JSON value or leak parser diagnostics. Only after that check does the current
SDK apply supported in-memory defaults. It does not rewrite persisted JSON or its
fingerprint. Additional editor-only columns do not affect codec 1. A new execution
column, incompatible storage encoding or execution-schema interpretation requires
an explicit codec/migration strategy; it must not silently extend codec 1.

The [native vector](../contracts/vectors/native-definition-v1.json) contains a
synthetic older SDK shape with omitted defaulted step fields, Unicode/NUL data,
independent Python-generated digest/byte count and the authenticated source wire
reference. The Rust file-reopen test applies today's defaults while retaining
identical stored bytes and fingerprints. This is not a fixture exported from a
released Swift/Android SDK; actual platform upgrade probes remain required.

## Publication input retention (staged)

The unpublished schema stores a versioned `delegation_publication_inputs` row
under the tenant/task key of its frozen manifest. It records the original
publication-request SHA, decoder-measured definition expansion, input codec,
exact input SHA/byte count and decoded input charge. The transaction inserts
this row with the frozen graph, mailbox, grant redemption and provenance; a
failed or suppressed input insertion aborts publication. The published v1 receipt
shape remains unchanged. Missing historical sidecars are not inferred from live
mailbox or catalog state.

Input preflight counts serialized bytes without allocating another serialized
copy before request hashing/cloning. Encoding retains the exact UTF-8 JSON bytes;
the stored body is a JSON string containing standard base64. EncryptingStorage
seals that string with field encryption before publication. The independent
logical SHA and charges describe the plaintext input, and do not change when
storage encryption is enabled. The stored representation has a separate 8 MiB
cap. Retention is immutable; acknowledged archival and compact receipts still
require integration before activation.

This storage foundation does not yet expose an input endpoint or qualify SQL
claim selection. Worker protocol/resource filtering, independently trusted claim
references, bounded transport and the scoped native execution bridge remain
required.

## Claimed input reads (staged)

`GET /workers/tasks/{id}/input?worker_id=...&claim_epoch=...` returns a
`DelegationInputEnvelope` with `Cache-Control: no-store`. It uses the definition
reader's issued-reporter, tenant, current claim, native/proxy state and continuity
ownership checks. Stored key/session authority is reauthorized before loading
and after response encoding. The immutable publication expiry is also checked
before and after encoding. Browser/device sessions permit only the exact UUID
route with GET; this grants no catalog or artifact access.

The storage adapter joins the immutable input sidecar to its publication receipt
and checks tenant/task/request identity and supported metadata. It bounds stored
body bytes to 8 MiB and receipt bytes to 64 KiB in SQL before transferring them.
The stored body must be a JSON string, including when it holds field ciphertext;
arrays/objects are rejected without decoding their elements. EncryptingStorage
decrypts the string, and the common bounded exact-byte input decoder verifies the
plaintext length, SHA and logical charge before an envelope is created.

Missing input evidence returns a conflict. Corrupt/unsupported retained data
fails without private parser/ciphertext diagnostics and is never replaced with
current mailbox or catalog content. Separate input and definition transport keeps
each bounded envelope below the mobile response cap. Trusted input references and
request identity still need atomic claim/poll delivery; a body digest or a read
response's self-reported reference does not establish independent provenance.
Worker resource filtering and scoped native execution remain required.

## Publication and lease resource admission (staged)

Publication checks the destination's explicit decoder contract against the
measured frozen closure and encoded input before grant redemption commits.
Missing or insufficient support rolls back definitions, input, mailbox and
provenance; an unchanged unspent grant can be retried after destination readiness
changes. Root-only and nested closure limits include both document and selector
counts as well as independent wire/decoded budgets.

Capability-aware SQL claims join immutable publication, manifest and input
metadata under the tenant/task/instance identity. They require matching original
request identity, supported codecs, sufficient counts/byte budgets and an unexpired
publication. These predicates run before the bounded discovery scan's LIMIT and
again during locked selection/mutation. Missing historical metadata is excluded
without consulting live mailbox/catalog content. Legacy selectors with no decoder
contract exclude reserved `orch8.delegation` tasks and publication-owned task IDs,
including when mutable handler/requirement fields change.

SQLite claims retain their selected order but return only rows actually changed
by the final guarded update. Runtime capability expiry is rechecked at that
mutation. PostgreSQL rechecks publication limits/expiry in both locked candidate
selection and update. Existing issued-generation heartbeats, outcome reports and
reconciliation are independent of new-claim decoder eligibility. This does not
activate the mobile provider bridge: mobile still advertises no protocol support.
Scoped native execution authority and acknowledged archive remain integration
requirements.

Device destination discovery requires a valid explicit decoder descriptor in
addition to liveness, trust and the delegation handler. Operator inventory still
includes unready runtimes. Discovery preserves decoder limits; publication remains
the authoritative fit check against the selected frozen closure and input.

## Issued reference context (staged)

A separate `worker_issued_delegation_contexts` sidecar pins codec-1
`DelegationClaimContext` to `(task_id, claim_epoch)` and the original tenant/worker.
It contains the text-safe full claim scope, original request SHA, publication
expiry, exact definition/input references and measured resource use. The stored
v1 issued-claim receipt is unchanged. Capture occurs in the lease transaction;
rejected or suppressed sidecar insertion rolls back the lease, issued receipt
and transition evidence. The sidecar is immutable and bounded to 16 KiB. Reads
join the original issued identity and validate the full scope; missing contexts
are not reconstructed from today's publication/catalog state.

`WorkerClaimBatch` returns tasks and their captured contexts from that transaction.
The API performs no second metadata read after committing the lease. New delegated
poll entries carry `delegation: DelegationClaimContext`, with empty `params` and
`context`; input bytes are fetched separately. Published mailboxes use attempt
`0`, matching their retained publication and dispatch effect. Claim epochs may
advance without creating a new business attempt. Consumers reject nonzero mailbox
attempts before preparation or payload reads. Ordinary task delivery and its
business retry attempts are unchanged.
The stored mailbox still retains its original v1 input/spec for factual history.
This removes duplicated input from polls but does not yet compact stored mailboxes,
externalize oversized checkpoints or impose an aggregate transport-byte budget
on all ordinary task batches. Those remain integration/long-running-resource gates.

Consumers use the trusted poll context's scope/reference/request identity when
verifying either payload endpoint. The text claim epoch avoids host JSON number
rounding for this protocol. Reading or validating the context does not authorize
provider execution: current lease, account/catalog/peer binding, ownership,
per-forward checks and physical admission are still required. Historical facts
continue to use their original issued receipt independently of new-protocol
eligibility. Mobile does not advertise support until its complete bridge is ready.


## gRPC delivery and reconnect (staged)

Protocol-v2 stream task JSON carries the same optional `delegation` context as
HTTP polls. Demand consumes the atomic transport batch, rather than dropping its
contexts through a task-only adapter. Delegated task params/context stay empty;
ordinary frames retain their existing shape. Unary legacy polling does not opt
into this descriptor-based delivery protocol.

Reconnect selects the exact retained context alongside the held generation in a
single query. The recorded reporter, tenant, worker and handlers
are filtered before LIMIT. Publication-certified decoder/resource admission is
also applied before LIMIT, so older incompatible/uncertified reserved tasks do
not hide compatible ordinary work. No descriptor means no delegated redelivery.
Missing, oversized, malformed or scope-mismatched sidecars are unavailable and
are never repaired from current publication data. Encryption wrappers carry the
compact metadata without decrypting discarded inline input.

Reconnect preserves the original claim epoch and references. It does not issue a
new claim, renew a lease, revoke a parallel connection holding that same claim,
or authorize provider execution. Clients must still confirm the current lease
and apply durable duplicate/callback admission. The gRPC client validates task
identity and independently checks the issued references against the decoder
profile advertised when it opened the session; malformed delivery retires that
session without logging private task content.

The mobile journal separately retains a bounded immutable issued context under
its original claim identity. New deliveries cannot restamp changed, missing or
corrupt recovery evidence. Typed fixed-origin native payload reads verify the
independent references, but do not choose a local account/catalog or authorize a
provider callback. The scoped execution bridge remains required before mobile
advertises protocol support.


Held-row screening also excludes terminal parents, quarantined native relays,
permanent physical retirements, captured/sealed sources and compensating forward
owners before the reconnect limit. Explicit lease durations require a live
heartbeat/claim anchor; explicit task deadlines must remain in the future. NULL
lease durations retain the separate server-default/confirmation policy. These
checks observe a read snapshot and do not replace per-forward physical admission
or current-lease confirmation. Original rows and issuance/outcome evidence remain
available to the independent reporting/reconciliation paths.


## Local worker peer ownership (staged)

A host-selected `CatalogWorkerPeer` pins one local account/catalog to a canonical
public HTTPS API base, remote tenant and UUID worker identity. It is not inferred
from a task, a payload URL or the ambient global node. The same API/tenant/worker
tuple cannot be rebound to another local scope or peer key in this database.
Legacy global node identities cannot be adopted into this path, including UUID
case variants. A backend worker identity must be distinct for each such binding.

The credential-free record is immutable, strictly versioned and at most 8 KiB.
Admission allows 128 records globally, 64 per account and 16 per catalog, including
retired owners. Retries and fresh sign-in handles reuse existing identity; old
account-epoch handles lose access. Current-peer checks fence the local scope and
verify the retained record. Matching an issued context only checks its tenant and
worker identity; independent remote authentication, lease confirmation and scoped
native admission remain required. No delegated execution support is advertised
solely because this binding exists.


Remote native ownership is staged separately from signed catalog requests. Local
initialization creates one paused native root from the verified retained graph and
input, with immutable provenance and a physical-owner index per configured API
base/task. Those rows do not confer current lease or provider authority. Generic
scheduler, credential, worker and context-free mobile paths reject the remote IDs;
explicit scoped forward admission is still required. A second account/catalog may
not adopt that root or create a duplicate. Acknowledged archive must retain compact
ownership/outcome dedup evidence before removing hot instance/graph/input data.
